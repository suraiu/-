## 3. 投稿スクリプト（scripts/*.py、scripts/README.md）

### 見つけた問題
1. **二重投稿のすき**：投稿が成功したあと、記録を書く前にタイムアウト・接続切れ・強制終了が起きると、次の実行で同じ投稿をもう一度出していた。Threadsの公開段階で 5xx が返った場合も同じ。
2. **同時実行で二重投稿**：cron が重なって2つ同時に動くと、同じ投稿を2回出せた（ロックがない）。
3. **例外処理のもれ**：接続が途中で切れたとき（`RemoteDisconnected`・`ConnectionResetError` など）は `PostError` にならず、素の例外でキュー全体が止まっていた。
4. **返信先の検査不足**：`reply_to` が別のSNSの投稿や自分自身を指していても検査を通り、いつまでも「待ち」になっていた。
5. **時刻**：`--now` や `scheduled_at` をUTC（`Z`）で書くと、表示がUTCのままだった。Python 3.9/3.10 は `Z` を読めず止まる（READMEは 3.9 以上と書いている）。

### 直したこと
- 送る直前に `queue_state.json` へ `"status": "sending"` を書き、成功したら `"posted"` にする。タイムアウト・接続切れ・5xx・IDが返らない場合は `"unknown"` にして、**自動では出し直さない**（人がSNSで確かめて消すと出し直す）。4xx など確実に出ていない失敗は記録を消して、次の実行で出し直す。古い形の記録（status なし）は「投稿済み」として扱う。
- `output/日付/queue.lock` でロック（AUTO_POST が true で本番のときだけ）。`.gitignore` に `output/**/queue.lock` を追加。
- 通信の例外をすべて `PostError`（秘密は伏せ字）にまとめた。
- `reply_to` が別のSNS・自分自身なら、キューの検査で止める。返信先が `posted` になるまで返信は出さない。
- 時刻はすべてJSTにそろえて比べ・表示する。`Z` 付きも読める。
- README の3章・7章を、今の動きに合わせて書き直した。

### 確かめたこと
- `python3 -m py_compile scripts/*.py`：OK。
- `--dry-run`：`post_threads.py`・`post_bluesky.py`・`post_queue.py`（見本キュー、JSTとUTCの `--now`）すべて正常。AUTO_POST が false のとき送信しないことも確認。
- ローカルのモックサーバー（127.0.0.1）での通し試験：時刻前は出さない／2回目は出さない／Threads公開段階の500で unknown になり出し直さない／人が消すと出し直す／返信（Threads・Bluesky）／ロック中は止まる／接続切れが `PostError` になる／画面・`queue_state.json` にトークン・パスワード・JWT が出ない。
- 秘密情報：値はURLに入れず、エラー本文も伏せ字にしている（OK）。

### 直していないこと（理由）
- 本物の Threads／Bluesky API には送っていない（トークンがまだ無い）。READMEどおり、最初の本番はオーナーの立ち会いで1本ずつ試す。
