# 品質チェック：Kindle第1巻「仕事のメール編」（2026-10-20）

対象：products/kindle/vol1_email/ の manuscript.md・kdp_listing.md・cover.html
確認画像（スマホ幅 460×1500）：scratchpad/qc_vol1/ の before の b_*.png と、修正後の a_top / a_t01 / a_t09 / a_t15 / a_app / a_tips.png

## 結論
**出版してよい**（下の修正を入れたあとの状態で）。ただし、manuscript.epub と manuscript.docx は修正前の古いものなので、build.sh で作り直してから提出すること。

## 見つけた問題
1. **【重大】出力例の改行が消える。** 引用（`>`）の中で続いている行が、pandoc では1つの段落にまとめられていた。EPUBではメールの行がつながり、出力例の中の「・」の箇条書き（候補日など）が1行に並び、「誤：〜 正：〜」も横に並んでいた。157か所。
2. 巻末の「テンプレ一覧」が3列の表で、スマホでは右がはみ出して読めなかった。また h2 なので、目次では「おわりに」の下に入っていた。
3. 表現の誤り・わかりにくい所
   - テンプレ24（2回目の催促）の頼み方：「1回目にいつ何を送ったか、2回目の催促をいつ送ったか」となっていて、いまから書くメールとの関係がずれていた。
   - テンプレ24の直し方：メールでは使えない「太字にしたいので」と書いていた。
   - テンプレ27：出力例が「請求書（（金額））」と、かっこが二重になっていた。
   - テンプレ41：「社外の勉強会の講師」とあるのに、内容は社内勉強会だった。
   - 第1章 基本2：箇条書きのあとの段落が「を、箇条書きで…」で始まっていて、EPUBでは文が途中から始まるように見えた。
4. 表記ゆれ：「貼りつけて」（ほかは「はりつけ」）、「一番」（ほかは「いちばん」）が1つずつ。「下さい」はなし（「ください」で統一済み）。「致します」はテンプレ56の、わざと入れた誤りの中だけ。
5. 作り話の体験談に読める言い方：「これは本当によくあります」「ほぼ毎回この一文を入れてくれました」（試したのは1回ずつなので、言いすぎ）。
6. 特定のAIサービスについての断定：「ChatGPTやClaudeなどの対話型AIなら、どれでも使える」「AIは前の会話を覚えているので」（サービスや設定によって変わる）。kdp_listing.md の「ふだん使っている対話型AIでそのまま使えます」も同じ。

## 直したこと
- 1 → 引用の中で続く行の終わりに `\`（強制改行）を入れた（157か所）。修正後の画像で、メールの行・箇条書き・誤／正が1行ずつ表示されることを確認した。EPUBとdocxの試し作成（scratchpadで実施）でもエラーは出なかった。
- 2 → 新しく h1「付録　すぐ引けるまとめ」を作り、一覧を表から「**お礼（01〜07）**：…」という段落の形に変えた。あわせて、価値を上げるために次の2つを付録に足した（300円の本の満足度を上げるため）。
  - 「万能の型」：基本1〜4をまとめた、どの場面にも使えるコピペ用の型
  - 「追加の注文」集：本文に散らばっていた直し方のひとことを、9つにまとめたもの
  - おわりに と kdp_listing.md の特長にも、付録があることを1行ずつ足した。
- 3 → テンプレ24の経緯を「最初にいつ何を送ったか、1回目の催促をいつ送ったか」に直した。直し方は「メールでは太字が使えないことが多いので【】でかこんで」にした。テンプレ27は「〇〇円」と書く形に変えた（頼み方・出力例・直し方の3か所）。テンプレ41は「社内勉強会の講師を引き受けてくれた社外の太田様」にした。基本2は「この3つを、箇条書きで…」で始めるようにした。
- 4 → 「はりつけて」「いちばん」に統一した。
- 5 → 「この本の出力例でも、何度か起きています」「この章の出力例でも、催促のメールの多くにこの一文が入っています」に変えた（どちらも本文の出力例で確かめた）。
- 6 → 「ふだん使っている対話型AIで使えるように、特定のサービスに頼らない書き方にしています。AIによって答え方のくせはちがう」とした。また「同じ会話の中なら前のやりとりをふまえてくれる。新しい会話では引きつがれないことがある」と直した。listing も同じように直した。

## 問題なしと確認したこと
- **日付と曜日**：本文の「〇月〇日（曜）」の56か所を、Pythonで2026年のカレンダーと照らし合わせた。すべて合っていた。合わないのはテンプレ56の「11月12日（水）」だけで、これはわざと残した誤りで、出力例の中で「木曜日です」と説明しているのでOK。曜日のない日付も、前後の話が合っていることを確かめた（例：テンプレ01→52の山田様、35→40の野口様の流れ）。
- **見出し**：h1 は章（この本について／はじめに／第1〜10章／おわりに／付録）、h2 は基本・テンプレ・付録の節になっている。テンプレの番号は01〜56が連番で、抜けも重なりもない。全角スペースの入った見出しも、pandoc のIDと目次で崩れていない。`#` のあとが全角スペースになっている見出しはなかった。
- **Markdown**：箇条書きの前には、すべて空行がある。コードブロックは56個で、開きと閉じの数が合っている。行の終わりの余計な空白もない。
- **外部の統計・数字**：出典が必要な統計はない。「〜と言われます」「〜かもしれません」と、言い切らない形になっている。
- **listing と本文の一致**：タイトル・サブタイトル・テンプレの数（56）・【収録している場面】の8項目は、本文の章と合っている。表紙の「56」も合っている。シリーズの第2巻・第3巻の名前も、それぞれの listing と合っている。
- **cover.html／cover.png**：文字は読みやすく、ブランドカラーを使っていて、はみ出しもない。変更はしていない。

## 直していないこととその理由
- **manuscript.epub／manuscript.docx の作り直し**：build.sh は触らない指示なので、作り直していない。今の2つのファイルは修正前のもの。社長が build.sh を作り直すときに、必ず作り直すこと。
- **目次の長さ**（--toc-depth=2 で約80項目）：テンプレ集は「場面で探してすぐ飛ぶ」ための本なので、テンプレ単位の目次は役に立つと判断して、そのままにした。各章の下にまとまっていて、崩れはない。短くするなら toc-depth=1 にする（これは build.sh 側の判断）。
- **出力例の中身**：「AIが実際に出した文章」と説明しているので、かっこが二重になっていた所（テンプレ27）以外は、文面を変えていない。
- **「ぷるの」がAIを試したという語り**：キャラクターの語りで、「この本について」と奥付で「AIが執筆し、出力例はAIの文章」と説明しているので、作り話の体験談には当たらないと判断した。
- **テンプレ12（10月18日・日曜に納品）、テンプレ06（土曜の懇親会のお礼を日曜に送る）**：曜日を書いておらず、ありえない日程でもないので、そのままにした。
- **kdp_listing.md の〔要確認〕（カテゴリ・300円が70％の価格範囲に入るか）**：KDPの画面でしか確かめられないので、登録する人の確認にまかせる。
- **cover.html の「56 こ」**：ゆるいトーンとして意図した書き方だと判断した。変えると cover.png を作り直す必要があるので、変えていない。
